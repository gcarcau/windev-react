# Impression d'un état en WEBDEV

> **Disponible :** **WEBDEV** (Windows)

Lors de la création d'un état, il est possible de tester directement cet état depuis l'éditeur d'états.
Il est également possible d'intégrer cet état à vos applications ou à vos sites. L'utilisateur ou l'internaute pourra ainsi lancer l'impression de l'état directement depuis un bouton ou une option de menu par exemple.

Dans le cas d'un site WEBDEV, le poste serveur se chargera de préparer l'état au format choisi (PDF, HTML, etc.). Selon vos besoins, vous pourrez alors :

- afficher cet état sur le navigateur de l'internaute,
- l'enregistrer sur le serveur et proposer à l'internaute de le télécharger ou de l'afficher, etc.

Dans un site Intranet, il est également possible d'imprimer directement l'état sur une imprimante locale ou réseau connectée au serveur.

## Principe d'impression en WEBDEV

Quel que soit le type d'état à imprimer, le principe de lancement d'un état est le suivant (en code serveur) :

1. Spécifier le mode d'impression de l'état (impression directe, génération d'une page HTML, génération d'un fichier PDF, etc.) avec la fonction [iDestination](3046074.md).
2. Lancer l'impression avec la fonction [iImprimeEtat](3046032.md).
3. Selon vos besoins, vous pourrez ensuite :
  - afficher le fichier généré sur le poste de l'internaute grâce à la fonction [FichierAffiche](3012005.md).
  - envoyer un email à l'internaute pour lui proposer de télécharger le fichier créé.
  - ...

**Attention** : Si la destination de l'impression est un fichier HTML, PDF, XML ou RTF, vérifiez les points suivants :

- Vous disposez des droits d'écriture dans le répertoire dans lequel le document va être généré (par défaut, le document est généré dans le répertoire du site).
  Si vous générez un état au format PDF, ce fichier peut être enregistré dans le répertoire des données (chemin connu avec la fonction [fRepDonnées](3036001.md))
  Si vous générez un état au format HTML, ce fichier doit être enregistré dans le répertoire _WEB du site (chemin connu avec la fonction [fRepWeb](3036052.md)).
- Utilisez un nom spécifique pour chaque document généré sur le serveur. Dans le cas contraire, plusieurs impressions simultanées écraseraient les impressions déjà réalisées.
  Utilisez par exemple les fonctions serveur [ConnexionOccurrence](3012004.md) ou [DonneIdentifiant](3013028.md) pour nommer vos états (par exemple : NomFichier = "EtatClient" + **ConnexionOccurrence**() + ".HTML").

Ce principe doit être adapté et complété selon la source de données utilisée dans chaque état.
