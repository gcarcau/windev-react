# Webservice REST sécurisé

> **Disponible :** **WINDEV** (Windows, Linux, Code Utilisateur (MCU)) · **WEBDEV** (Windows, Linux)

## Présentation

WINDEV et WEBDEV permettent de créer des Webservices REST à accès sécurisé par token OAuth.
Le principe est le suivant :

L'accès au Webservice nécessite la fourniture d'un token.
L'appelant du Webservice doit donc obtenir ce token.
Un protocole standard pour obtenir ce token est OAuth.
Rappel : OAuth permet de gérer des autorisations d'accès.
Ce token est fourni par un serveur d'authentification, basé sur un protocole OAuth.

## Création d'un Webservice REST sécurisé

Pour créer un Webservice REST sécurisé, il suffit de :

1. Créer le Webservice REST. Pour plus de détails, consultez [Créer et utiliser un Webservice REST](1000022792.md).
2. Définir le(s) serveur(s) d'authentification (OpenID Connect) ou d'autorisation (OAuth 2.0).
3. Définir les permissions (scopes) en cas d'utilisation d'OAuth 2.0.
4. Associer les scopes aux points d'entrée.

### Définir les autorisations
Pour définir les autorisations associées à un Webservice REST :

1. Affichez si nécessaire le Webservice REST sous l'éditeur de Webservice REST.
2. Affichez la description du Webservice REST : sous le volet "Webservice REST", dans le groupe "Options", cliquez sur "Description".
3. Affichez l'onglet "Autorisation" de la fenêtre de description.

**Définir les serveurs de confiance**
Il est tout d'abord nécessaire de saisir les informations concernant les serveurs de confiance, permettant de vérifier l'authentification ou les autorisations des utilisateurs.
Pour définir le(s) serveur(s) d'authentification (OpenID Connect) ou d'autorisation (OAuth 2.0) :

- Dans la partie haute de la fenêtre, cliquez sur "+" pour ajouter autant de serveurs que voulu.
- Saisissez les caractéristiques de chaque serveur :
  - Adresse du serveur,
  - Clé utilisée pour la validation du token **ou** URL d'introspection fournies par le serveur (un seul de ces éléments est nécessaire).

Clé pour la validation du token (vérification de la signature).
La clé dépend de la signature utilisée par le serveur :

- Signatures "HS256"/"HS384"/"HS512" : la clé est la clé secrète (partagée avec le serveur). La clé est généralement une valeur binaire, parfois représentée sous forme d'une chaîne en hexadécimal.
- Signatures "RS256"/"RS384"/"RS512" : la clé est la clé publique du serveur. La clé est une chaîne. Elle est généralement représentée sous la forme d'un texte multiligne qui commence par ----BEGIN PUBLIC KEY-----

**Définir les permissions (scope)**
Dans la partie basse de la fenêtre, il est possible de saisir la liste des permissions pouvant être nécessaires pour exécuter un point d'entrée du Webservice.

Pour associer les permissions aux points d'entrée, il suffit pour chaque point d'entrée de cliquer sur le bouton "Permission" et de sélectionner la ou les permissions nécessaires.
Attention : Si aucune permission n'est sélectionnée, le point d'entrée sera utilisable sans restriction particulière.
