# Les différents types de parcours disponibles en SQL

> **Disponible :** **WINDEV** (Windows, Linux, Java) · **WEBDEV** (Windows, Linux, PHP)

## Présentation

Pour parcourir le résultat d'une requête exécutée avec la fonction [SQLExec](3072007.md), deux types de parcours sont disponibles :

- Parcours de type : [SQLPremier](3072017.md)/[SQLCol](3072018.md)
- Parcours de type : [SQLAvance](3072011.md)/[SQLLitCol](3072019.md).

Les paragraphes suivants présentent les avantages et les inconvénients de chacune de ces deux méthodes.

## Comparaison des deux méthodes

Le tableau suivant présente les caractéristiques des deux méthodes de parcours :

|  | **Parcours de type SQLPremier/SQLCol** | **Parcours de type SQLAvance/SQLLitCol** |
| --- | --- | --- |
| **Résultat de la requête** | Tous les enregistrements résultat de la requête sont chargés en mémoire lors de l'exécution de la fonction [SQLPremier](3072017.md). Le premier appel à la fonction [SQLPremier](3072017.md) peut être relativement long. | Aucun enregistrement n'est chargé en mémoire. La base de données gère le résultat de la requête. |
| **Nombre d'enregistrements** | Le nombre d'enregistrements correspondant au résultat de la requête est automatiquement calculé lors de la lecture du premier enregistrement (fonction [SQLPremier](3072017.md)). La variable SQL.NbLig est mise à jour | Le nombre d'enregistrements correspondant au résultat de la requête n'est pas calculé. |
| **SQLInfoGene** | La fonction [SQLInfoGene](3072028.md) permet d'obtenir des renseignements sur la requête et sur le parcours en cours. | La fonction [SQLInfoGene](3072028.md) permet uniquement d'obtenir des informations générales sur la requête ou sur la connexion. |
| **Parcours des enregistrements** | Retour possible sur un élément précédent du résultat | Pas de retour possible sur un élément précédent du résultat |
|  | Lecture du résultat de la requête grâce aux fonctions [SQLCol](3072018.md), [SQLAssocie](3072004.md). | Lecture du résultat de la requête grâce à la fonction [SQLLitCol](3072019.md) et [SQLLitMémo](3072020.md). |
| **Affichage dans une table** | La fonction [SQLTable](3072031.md) ne doit pas être utilisée (erreur fatale). | La fonction [SQLTable](3072031.md) permet de récupérer uniquement les enregistrements résultat à partir de l'enregistrement en cours. |
| **Gestion des tabulations** | Ce type de parcours ne permet pas de récupérer les tabulations présentes dans les valeurs des enregistrements. Une tabulation sépare deux rubriques. Seule la partie précédant la tabulation sera récupérée avec les fonctions de lecture.  Pour plus de détails, consultez l'aide de [SQLCol](3072018.md) et [SQLAssocie](3072004.md). | Ce type de parcours permet de récupérer les tabulations présentes dans les valeurs des enregistrements. Pour plus de détails, consultez l'aide de [SQLLitCol](3072019.md). |

**Exemple de parcours de type SQLPremier/SQLCol**
```wlangage
ResExec = SQLExec("SELECT NOMCLI FROM FACT","REQ1")
SI ResExec ALORS
	SQLPremier("REQ1")
	// Transfert du nom dans LISTE_LISTENOM
	TANTQUE PAS SQL.EnDehors
		ListeAjoute(LISTE_LISTENOM, SQLCol("REQ1",1))
		SQLSuivant("REQ1")
	FIN
SINON
	// TraiteErreur
FIN
SQLFerme("REQ1")
```

**Exemple de parcours de type SQLAvance/SQLLitCol**

```wlangage
i est un entier = 0
SQLExec("SELECT NOM, PRENOM, POSTE,PHOTO FROM CLIENT","REQ1")
// Récupérer la requête ligne à ligne
TANTQUE SQLAvance("REQ1") = 0
	// Il y a encore une ligne
	i++
	// Récupérer les données
	NOM[i] = SQLLitCol("REQ1",1)
	PRENOM[i] = SQLLitCol("REQ1", 2)
	POSTE[i] = SQLLitCol("REQ1",3)
	{"IMAGE"+i} = SQLLitMémo("REQ1", 4)
FIN
SQLFerme("REQ1")
```
