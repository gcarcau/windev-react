# <Variable Connexion>.ExécuteProcédureAsynchrone (Fonction)

> **Disponible :** **WINDEV** (Windows, Linux, Java, Etats et Requêtes, Code Utilisateur (MCU)) · **WEBDEV** (Windows, Linux) · **WINDEV Mobile** (Android, Widget Android, iPhone/iPad, Widget IOS)

Exécute une procédure stockée en mode asynchrone.
Nouveauté Abonnement
Cette fonction est une nouveauté disponible uniquement dans la version Abonnement à partir de WINDEV Suite 2025 Update 2.
Pour plus de détails, consultez [Utiliser les nouveautés de WINDEV Suite 2025 spécifiques à l'abonnement](1410087359.md).

## Exemple

```wlangage
PROCÉDURE INTERNE MaCallbackCliente(CResultatPS est un Variant)
		Trace("Ma callback " + CResultatPS)
FIN
soit sRésultat = MaConnexion1.ExécuteProcédureAsynchrone(ProcédureStockée, (ParametreP), MaCallbackCliente)
Trace(sRésultat)
Trace("fin PS")
```

## Syntaxe

```wlangage
<Connexion>.ExécuteProcédureAsynchrone(<Procédure stockée> , <Paramètre 1> ... [, <Paramètre N> [, <Procédure WLangage de fin>]])
```

`<Connexion>` *Variable de type Connexion*
> Nom de la variable de type [Connexion](1514073.md) correspondant à la connexion vers le serveur qui exécute la procédure stockée.
`<Procédure stockée>` *Procédure WLangage*
> Nom de la procédure stockée à exécuter.
`<Paramètre 1>` *Variant optionnel*
> Premier paramètre à passer à la procédure <Procédure stockée>.
`<Paramètre N>` *Variant optionnel*
> Nième paramètre à passer à la procédure <Procédure stockée>.
`<Procédure WLangage de fin>` *Nom de procédure optionnel*
> Procédure WLangage (également nommée "callback") exécutée à la fin de l'exécution de la procédure. Cette procédure est de la forme :
>
>
> ```wlangage
> PROCEDURE Nom_Procédure(<Retour> est un variant)
> ```
>
>
>  où <Retour> correspond au retour de la procédure stockée.
>
> - La variable [ErreurDétectée](3087001.md) utilisée dans cette procédure est à Vrai si la procédure stockée à rencontrée une erreur (erreur d'exécution, perte de la connexion, etc.).
>   En cas de reconnexion automatique, la fonction **<Variable Connexion>.ExécuteProcédureAsynchrone** n'est pas rappelée automatiquement.
> - Cette procédure s'exécute dans la copie du contexte HFSQL réalisée lors de l'appel à la fonction **<Variable Connexion>.ExécuteProcédureAsynchrone**.

## Remarques

### Gestion automatique des erreurs
La gestion automatique des erreurs est désactivée dans les procédures stockées. Il est cependant possible d'utiliser la fonction [<Source>.SurErreur](1000025073.md) pour exécuter une procédure spécifique (procédure stockée).

### Passage de paramètres
Les paramètres passés à la procédure stockée sont passés "par valeur" : si ces paramètres sont modifiés dans la procédure stockée, ils ne seront pas modifiés dans l'application qui a exécuté cette procédure stockée (fonctionnement inverse de la fonction [<Variable Connexion>.ExécuteProcédure](1000022659.md)).

### Exécution d'une procédure stockée depuis un code SQL
Une procédure stockée peut être appelée :

- depuis du code SQL, par exemple avec les fonctions [<Source>.ExécuteRequêteSQL](1000024948.md) ou [SQLExec](3072007.md),
- depuis une application tierce utilisant le [driver ODBC pour HFSQL](9000160.md) ou le [provider OLE DB pour HFSQL](9000059.md).

Pour plus de détails, consultez [Procédures et requêtes stockées (HFSQL Client/Serveur)](3044360.md).
