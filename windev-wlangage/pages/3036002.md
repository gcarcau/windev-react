# fCompare (Fonction)

> **Disponible :** **WINDEV** (Windows, Linux, Java, Etats et Requêtes, Code Utilisateur (MCU)) · **WEBDEV** (Windows, Linux, PHP) · **WINDEV Mobile** (Android, Widget Android, iPhone/iPad, Widget IOS, Mac Catalyst) · **Autres** (Procédures stockées)

Compare bit à bit le contenu de deux fichiers.

## Exemple

> _(WINDEV, WEBDEV - Code Serveur, Etats et Requêtes, Java, Code Utilisateur (MCU), PHP, Ajax)_ // Comparaison du contenu de deux fichiers
Res = fCompare("C:\Répertoires\FichierA.doc", "C:\Répertoires\FichierB.doc")

## Syntaxe

```wlangage
<Résultat> = fCompare(<Chemin du fichier 1> , <Chemin du fichier 2>)
```

`<Résultat>` *Entier*
> - 0 si les deux fichiers sont identiques ou si les deux chemins de fichier sont identiques,
> - 1 si les deux fichiers sont différents,
> - un code d'erreur (valeur inférieure à 0) dans les autres cas.
`<Chemin du fichier 1>` *Chaîne de caractères*
> Nom et chemin complet (ou relatif) du premier fichier à comparer (260 caractères maximum). Un chemin de type UNC peut être utilisé.
> > _(Windows, Linux)_ Ce paramètre peut être au format Ansi ou Unicode.
>
> > _(Android, Widget Android)_ Ce paramètre peut correspondre à un chemin complet ou relatif par rapport au répertoire en cours (connu avec la fonction fRepEnCours). Ce paramètre est sensible à la casse. Rappel : Sous Android, sur l'appareil comme sur l'émulateur, le système de fichiers est en lecture seule. Une application a uniquement le droit d'écrire dans son répertoire d'installation ou dans un de ses sous-répertoires, ainsi que sur la mémoire externe (SDCard).
>
> > _(iPhone/iPad, Widget IOS, Mac Catalyst)_ Le chemin du fichier peut correspondre à un chemin complet ou relatif par rapport au répertoire en cours (connu avec la fonction fRepEnCours). Ce paramètre est sensible à la casse. Rappel : Sous les iPhone/iPad, sur l'appareil comme sur l'émulateur, le système de fichiers est en lecture seule. Une application a uniquement le droit d'écrire dans son répertoire d'installation ou dans un de ses sous-répertoires.
`<Chemin du fichier 2>` *Chaîne de caractères*
> Nom et chemin complet (ou relatif) du second fichier à comparer (260 caractères maximum). Un chemin de type UNC peut être utilisé.
>
> > _(Windows, Linux)_ Ce paramètre peut être au format Ansi ou Unicode.
>
> > _(Android, Widget Android)_ Ce paramètre peut correspondre à un chemin complet ou relatif par rapport au répertoire en cours (connu avec la fonction fRepEnCours). Ce paramètre est sensible à la casse. Rappel : Sous Android, sur l'appareil comme sur l'émulateur, le système de fichiers est en lecture seule. Une application a uniquement le droit d'écrire dans son répertoire d'installation ou dans un de ses sous-répertoires, ainsi que sur la mémoire externe (SDCard).
>
> > _(iPhone/iPad, Widget IOS, Mac Catalyst)_ Ce paramètre peut correspondre à un chemin complet ou relatif par rapport au répertoire en cours (connu avec la fonction fRepEnCours). Ce paramètre est sensible à la casse. Rappel : Sous les iPhone/iPad, sur l'appareil comme sur l'émulateur, le système de fichiers est en lecture seule. Une application a uniquement le droit d'écrire dans son répertoire d'installation ou dans un de ses sous-répertoires.

## Remarques

### Code d'erreur
Les codes d'erreur retournés sont les suivants :

- -1 : Le <Chemin du fichier 1> n'a pas été trouvé.
- -2 : Le <Chemin du fichier 2> n'a pas été trouvé.
- -3 : Erreur pendant la comparaison :
  - un des fichiers à comparer est ouvert, bloqué ou n'existe pas;
  - le chemin de l'un des fichiers à comparer est invalide;
  - l'utilisateur n'a pas les droits en lecture sur l'un des fichiers à comparer;
  - pas assez de mémoire disponible pour effectuer la comparaison.

Le message correspondant au code d'erreur peut être connu grâce à la fonction [ErreurInfo](3013008.md) avec la constante *errMessage*.
