# HTransactionIsolation (Fonction)

> **Disponible :** **WINDEV** (Windows, Linux, Java, Etats et Requêtes, Code Utilisateur (MCU)) · **WEBDEV** (Windows, Linux) · **WINDEV Mobile** (Android, Widget Android, iPhone/iPad, Widget IOS, Mac Catalyst)

Configure le mode d'isolation des transactions pour une connexion vers un serveur HFSQL.
En fonction du mode sélectionné, une application effectuant des lectures aura accès ou non aux données en cours de modification dans une transaction par une autre application, ou une autre instance de la même application.

Pour plus de détails sur les modes d'isolation, consultez [Transactions Client/Serveur : Modes d'isolation disponibles](1000017316.md).

## Exemple

```wlangage
MaConnexion est une Connexion
HTransactionIsolation(MaConnexion, hReadCommitted)
HLitPremier(MonFichierClient, MaClé)
```

## Syntaxe

```wlangage
<Résultat> = HTransactionIsolation(<Connexion> , <Mode d'isolation>)
```

`<Résultat>` *Booléen*
> - Vrai le niveau d'isolation a été mis en place,
> - Faux en cas d'erreur. La fonction [HErreurInfo](3044071.md) permet d'identifier l'erreur.
`<Connexion>` *Chaîne de caractères ou variable de type Connexion*
> Connexion vers un serveur HFSQL. Cette connexion correspond :
>
> - soit au nom de la connexion définie sous l'éditeur d'analyses ou grâce aux fonctions [HDécritConnexion](3044205.md) ou [HOuvreConnexion](3044107.md).
> - soit au nom d'une variable de type [Connexion](1514073.md).
`<Mode d'isolation>` *Constante de type Entier*
> Mode d'isolation choisi :
>
> | *hReadCommitted* | Seules les transactions finalisées sont visibles par les autres utilisateurs. |
> | --- | --- |
> | *hReadUncommitted* | Les transactions non finalisées sont visibles par les autres utilisateurs. |
> | *hRepeatableRead* | L'application en transaction voit un instantané de la base à l'instant où démarre la transaction. |

**Composante : wd300hf.dll**
