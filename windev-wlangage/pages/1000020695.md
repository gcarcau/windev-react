# EnModeWindowsStoreApp (Fonction)

> **Disponible :** **WINDEV** (Windows, Linux, Java, Etats et Requêtes, Code Utilisateur (MCU)) · **WEBDEV** (Windows, Linux, PHP) · **WINDEV Mobile** (Android, Widget Android, iPhone/iPad, Widget IOS, Apple Watch, Mac Catalyst)

Identifie si le code est exécuté en mode Windows Store apps ou non.

## Exemple

```wlangage
// Code exécuté en Windows Store apps ?
SI EnModeWindowsStoreApp() = Vrai ALORS
	// Code spécifique à la plateforme Windows Store apps
FIN
```

## Syntaxe

```wlangage
<Résultat> = EnModeWindowsStoreApp()
```

`<Résultat>` *Booléen*
> - Vrai si le code est exécuté en mode Windows Store apps (sur le poste utilisant Windows 8 en mode tuile),
> - Faux dans le cas contraire.

## Remarques

### Disponibilité de la fonction
La fonction **EnModeWindowsStoreApp** est disponible dans tous les produits pour permettre l'écriture d'un code multi-produits. Des fonctions ou procédures utilisant la fonction **EnModeWindowsStoreApp** peuvent être partagées entre plusieurs produits, sans que des erreurs de compilation soient générées.

### Exécution des traitements contenant des erreurs de compilation
Par défaut, le mécanisme de sécurité du WLangage se déclenche uniquement si la ligne contenant l'erreur de compilation est exécutée.
Par exemple, si une fonction interdite dans le produit en cours est présente dans une boucle SI, le mécanisme de sécurité du WLangage se déclenchera uniquement si la ligne contenant cette fonction s'exécute.

**Composante : wd300vm.dll**
