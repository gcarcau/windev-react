# ShamirCréeClésPartagées (Fonction)

> **Disponible :** **WINDEV** (Windows, Linux, Etats et Requêtes, Code Utilisateur (MCU)) · **WEBDEV** (Windows, Linux) · **WINDEV Mobile** (Android, Widget Android, iPhone/iPad, Widget IOS, Mac Catalyst)

Crée un ensemble de clés pour un même secret selon l'algorithme de Shamir.
Le principe est le suivant :

- Un "secret" est découpé en un certain nombre de clés.
- Pour reconstituer le "secret", il est nécessaire d'avoir un nombre minimum de clés.

Nouveauté Abonnement
Cette fonction est une nouveauté disponible uniquement dans la version Abonnement à partir de WINDEV Suite 2025 Update 4.
Pour plus de détails, consultez [Utiliser les nouveautés de WINDEV Suite 2025 spécifiques à l'abonnement](1410087359.md).

## Exemple

```wlangage
// Définition des paramètres d'entrée
secret est un Buffer = "Mon super secret"
nombre_de_clés_a_générer est un entier = 5
nombre_de_clés_nécessaires_pour_reconstitution est un entier = 3

// Tableau des clés générées
clés_genérées est un tableau de chaînes
// Génération des clés
clés_genérées = ShamirCréeClésPartagées(secret, nombre_de_clés_a_générer,
			nombre_de_clés_nécessaires_pour_reconstitution)
// Découpage des clés pour création de bip39 + stockage dans des fichiers
POUR CHAQUE clé DE clés_genérées
	// Trace(clé)
	// Découpe la clé en sections
	sections_de_la_clé est un tableau de chaînes = ChaîneDécoupe(clé, "-")
	// Récupère l'identifiant de la clé
	// la première section est toujours l'identifiant
	id est un entier = sections_de_la_clé[1]
	// Crée un bip39 de chaque section de 256 bits
	tab_bip39 est un tableau de chaînes
	// Si le nombre premier n'a pas été renseigné,
	// les sections suivantes sont la valeur de la clé découpée en morceaux de maximum 256 bits
	// Sinon
	// il n'y a qu'une seule section après l'identifiant,
	// la taille de la section est <= à la taille du nombre premier
	POUR indice_section = 2 _À_ sections_de_la_clé.Occurrence
		// Transforme l'hexa en buffer puis le buffer en bip39
		buffer_section est un Buffer = HexaVersBuffer(sections_de_la_clef[indice_section])
		bip39_section est une chaîne = BufferVersPhrase(buffer_section, langueFrançais)
		// Ajoute le bip39 au tableau des bip39 de la clé
		tab_bip39.Ajoute(bip39_section)
	FIN
	// Sauvegarde les bip39 dans un fichier
	fSauveTexte(fRepExe() + [fSep()] + "bip39_cle_[%id%].txt", tab_bip39.VersChaîne(RC))
FIN
```

## Syntaxe

```wlangage
<Résultat> = ShamirCréeClésPartagées(<Secret> , <Nombre de clés> , <Seuil> [, <Nombre premier>])
```

`<Résultat>` *Tableau*
> Tableau de chaînes de caractères contenant les différentes clés générées.
`<Secret>` *Buffer*
> Buffer secret à "découper".
`<Nombre de clés>` *Entier*
> Nombre total minimum de clés à créer.
`<Seuil>` *Entier*
> Nombre minimum de clés nécessaires à la reconstitution du secret.
`<Nombre premier>` *Chaîne de caractères optionnelle*
> Nombre premier représenté sous une chaîne Hexadécimale. Ce nombre doit être identique lors de la création et lors de la reconstitution du secret.
> Si ce paramètre n'est pas spécifié, les clés seront découpées en sections de 256 bits.
> Si ce paramètre est spécifié, ce nombre premier doit être plus grand que le <Secret>. La fonction [ShamirGénèreNombrePremier](1410091295.md) permet de générer un nombre premier ayant la taille voulue.

## Remarques

Le partage de clé secrète de Shamir est un algorithme de cryptographie sous forme de secret réparti : un secret est divisé en parties, donnant à chaque participant sa propre clé partagée. Certaines des parties ou l'ensemble d'entre elles sont nécessaires afin de reconstruire une phrase de passe qui donne accès au secret.
Tous les participants ne sont pas obligatoirement nécessaires pour reconstituer le minimum nécessaire qui forme la phrase de passe d'accès au secret : on définit un <Seuil>.
