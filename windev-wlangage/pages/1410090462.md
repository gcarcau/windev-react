# HRplAjouteFichier (Fonction)

> **Disponible :** **WINDEV** (Windows, Linux, Etats et Requêtes, Code Utilisateur (MCU)) · **WEBDEV** (Windows, Linux) · **WINDEV Mobile** (Android, Widget Android, iPhone/iPad, Widget IOS)

Ajoute un fichier de données dans une réplication universelle.
**Attention** : Le fichier de données physique correspondant doit exister sur le poste abonné.

## Exemple

```wlangage
HRplAjouteFichier("P:\MSG\MSG.RPM", "Paris", "NouveauFichierARépliquer")
```

## Syntaxe

```wlangage
<Résultat> = HRplAjouteFichier(<Répertoire du Réplica Maître> , <Identifiant> , <Liste des tables à répliquer>)
```

`<Résultat>` *Booléen*
> - Vrai si le ou les fichiers de données ont été ajoutés à la réplication,
> - Faux dans le cas contraire.
`<Répertoire du Réplica Maître>` *Chaîne de caractères*
> Répertoire où le fichier de description du Réplica Maître (fichier "rpm") a été créé (fonction [HCréeRéplicaMaître](3044175.md)). Ce répertoire peut être un répertoire réseau ou un chemin UNC.
> Si ce paramètre correspond à une chaîne vide (""), le fichier de description sera recherché dans le répertoire en cours des fichiers de données HFSQL (défini sous l'éditeur d'analyses ou par programmation).
> **Attention** : Ce répertoire doit être accessible lors de l'exécution de la fonction **HRplAjouteFichier**.
`<Identifiant>` *Entier ou chaîne de caractères*
> Identifiant du Réplica Abonné. Cet identifiant a été renvoyé par la fonction [HCréeRéplicaAbonné](3044253.md). Cet identifiant pourra être utilisé par la fonction [hCréeRéplicaTransportable](3044209.md).
`<Liste des tables à répliquer>` *Chaîne de caractères*
> Cette liste est de la forme :
>
>
> ```wlangage
> <Nom du fichier de données> [+ TAB + <Nom de la rubrique date>] [+ <RC> + <Nom du fichier de données 2> [+ TAB + <Nom de la rubrique date 2>]]...
> ```
>
>
>
> **Attention** :
>
>
> - L'ordre des fichiers de données est important. L'ordre des fichiers de données est l'ordre des dépendances des fichiers de données (voir Remarques).
> - Le nom de la rubrique Date est obligatoire pour des bases de données différentes de HFSQL. Cette rubrique doit correspondre à une rubrique du fichier de données mise à jour lors d'un ajout ou d'une modification de l'enregistrement correspondant. Cette opération doit être effectuée par l'application.

## Remarques

### Liste des fichiers de données à répliquer
La liste des fichiers de données à répliquer doit être fournie en utilisant la syntaxe :

```wlangage
<Nom du fichier de données> [+ TAB + <Nom de la rubrique date>] [+ <RC> + <Nom du fichier de données 2> [+ TAB + <Nom de la rubrique date 2>]]...
```

L'ordre des fichiers de données est important. L'ordre des fichiers de données est l'ordre des dépendances des fichiers de données.

Prenons l'exemple suivant :

- Les enregistrements d'un fichier de données 1 sont liés à ceux d'un fichier de données 2.
- L'enregistrement doit être présent dans le fichier de données 2 pour que l'ajout dans le fichier de données 1 respecte les règles d'intégrité.

Dans ce cas, il faut placer le fichier de données 1 en premier dans la liste.
En adaptant cet exemple au cas des fichiers de données "Client", "Commande" et "Ligne de commande" (qui sont reliés par des liaisons de cardinalités (0,n) - (1,1)), il faut placer :

- le fichier de données "Client" en premier (pour ajouter une commande, il faut un client),
- puis le fichier de données "Commande" (pour ajouter une ligne de commande, il faut une commande),
- et enfin le fichier de données "Ligne de commande".
