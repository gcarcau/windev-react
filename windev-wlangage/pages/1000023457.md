# EnModeArrièrePlan (Fonction)

> **Disponible :** **WINDEV** (Windows, Linux, Etats et Requêtes, Code Utilisateur (MCU)) · **WEBDEV** (Windows, Linux, PHP, WEBDEV - Code Navigateur) · **WINDEV Mobile** (Android, iPhone/iPad, Widget IOS, Apple Watch, Mac Catalyst)

Identifie si le code est exécuté alors que l'application est en arrière-plan.
Rappel : Une application est considérée comme étant en arrière-plan lorsqu'aucune de ses fenêtres n'est visible à l'écran.

## Exemple

```wlangage
// Si l'application n'est pas en arrière-plan, on peut afficher une boîte de dialogue,
// sinon on effectue une notification
SI PAS EnModeArrièrePlan() ALORS
	Info("Traitement terminé")
SINON
	n est une Notification
	n.Message = "Traitement terminé"
	NotifAjoute(n)
FIN
```

## Syntaxe

```wlangage
<Résultat> = EnModeArrièrePlan()
```

`<Résultat>` *Booléen*
> - Vrai si le code s'exécute alors que l'application est en arrière-plan,
> - Faux dans le cas contraire.
>
>
> > _(WEBDEV - Code Navigateur)_ Ce paramètre correspond toujours à Faux.

## Remarques

### Disponibilité de la fonction
La fonction **EnModeArrièrePlan** est disponible dans tous les produits pour permettre l'écriture d'un code multi-produits. Des fonctions ou procédures utilisant la fonction **EnModeArrièrePlan** peuvent être partagées entre plusieurs produits, sans que des erreurs de compilation soient générées.

### Exécution des traitements contenant des erreurs de compilation
Par défaut, le mécanisme de sécurité du WLangage se déclenche uniquement si la ligne contenant l'erreur de compilation est exécutée.
Par exemple, si une fonction interdite dans le produit en cours est présente dans une boucle SI, le mécanisme de sécurité du WLangage se déclenchera uniquement si la ligne contenant cette fonction s'exécute.

**Classification Métier / UI : Code neutre**

**Composante : wd300java.dll**
