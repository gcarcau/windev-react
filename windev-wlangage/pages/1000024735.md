# dbgConnecte (Fonction)

> **Disponible :** **WINDEV** (Windows, Linux, Etats et Requêtes, Code Utilisateur (MCU)) · **WEBDEV** (Windows, Linux) · **WINDEV Mobile** (iPhone/iPad, Widget IOS, Apple Watch, Mac Catalyst)

Permet de connecter un débogueur à distance sur une application, un service, un Webservice, ...

## Exemple

```wlangage
// Lance le débogueur à distance
dbgConnecte("1.1.1.1")
```

## Syntaxe

```wlangage
<Résultat> = dbgConnecte(<Débogueur>)
```

`<Résultat>` *Booléen*
> - Vrai si la connexion a réussi,
> - Faux dans le cas contraire.
`<Débogueur>` *Chaîne de caractères*
> Nom ou adresse IP de la machine de développement.

## Remarques

- Le débogueur doit être en attente de connexion avant que l'application à déboguer n'appelle la fonction **dbgConnecte**. Pour passer le débogueur en attente, utilisez au choix :
  - l'option "Attendre une connexion par dbgConnecte" dans le menu du bouton GO de projet.
  - sous le volet "Projet", dans le groupe "Mode test", déroulez "Mode test" et sélectionnez l'option "Attendre une connexion par dbgConnecte".
- La communication s'effectue depuis la machine du Serveur d'application sur le port 27280 en direction de la machine de développement. Il est donc nécessaire que ce port soit accessible sur la machine de développement, c'est-à-dire ouvert dans son pare-feu local et redirigé au niveau du proxy ou du routeur du réseau sur lequel se trouve cette machine.

**Classification Métier / UI : Code neutre**

**Composante : wd300vm.dll**
