# Gérer les mutex dans les threads

> **Disponible :** **WINDEV** (Windows, Linux, Etats et Requêtes, Code Utilisateur (MCU)) · **WEBDEV** (Windows, Linux) · **WINDEV Mobile** (iPhone/iPad)

## Présentation

Les mutex permettent de limiter l'exécution simultanée d'un code (procédure, ligne de code, ...) à un thread à un instant donné. Un mutex peut être partagé par plusieurs applications.
**Remarque** : D'autres systèmes permettent également de protéger une partie de code :

- les **sémaphores** permettent de limiter l'exécution simultanée d'un code (procédure, ligne de code, ...) **à un ou plusieurs threads** à un instant donné. Un sémaphore peut être partagé par plusieurs applications.
- les sections critiques permettent de limiter l'exécution simultanée d'un code (procédure, ligne de code, ...) **à un thread** à un instant donné dans une seule application.

## Principe

Le mutex a été créé avec la fonction [MutexCrée](1000019022.md).

1. Le thread n°1 exécute la fonction [MutexDébut](1000019023.md) : aucun thread n'est actuellement présent dans le mutex.
2. Le thread n°1 exécute la partie de code protégée par le mutex.
3. Pendant que le thread n°1 exécute le code protégé par le mutex, un thread n°2 exécute la fonction [MutexDébut](1000019023.md) : le code protégé par le mutex étant déjà en cours d'exécution par le thread n°1, le thread n°2 attend le déblocage du mutex.
4. Le thread n°1 exécute la fonction [MutexFin](1000019024.md) : plus aucun thread n'exécute le code du mutex.
5. Le thread n°2 peut exécuter le code protégé par le mutex.
6. Le thread n°2 exécute la fonction [MutexFin](1000019024.md) : plus aucun thread n'exécute le code du mutex.

## Comment mettre en place un mutex ?

### Les étapes :
Les différentes étapes de la mise en place d'un mutex sont les suivantes :

1. Création d'un mutex avec la fonction [MutexCrée](1000019022.md). Le mutex est associé à un nom.
2. Appel de la fonction [MutexDébut](1000019023.md) avant la portion de code à protéger.
3. Appel de la fonction [MutexFin](1000019024.md) pour délimiter la portion de code à protéger. Les lignes de code situées après la fonction [MutexFin](1000019024.md) ne seront plus protégées.
4. Destruction du mutex avec la fonction [MutexDétruit](1000019025.md).

### Remarques

- Les parties de code protégées par un mutex doivent être les plus courtes possibles et concerner uniquement des traitements "critiques".
- Lorsqu'un thread est en attente, les ressources du processeur ne sont pas utilisées.
- Les mutex s'appliquent aussi bien au thread principal qu'aux threads secondaires (créés avec la fonction [ThreadExécute](3077024.md)). Il est nécessaire d'éviter le blocage du thread principal. En effet, si le thread principal est bloqué (en attente), l'application ne peut plus s'exécuter.
- Les fonctions [MutexDébut](1000019023.md) et [MutexFin](1000019024.md) doivent être utilisées dans le même traitement (par exemple dans une procédure).
- Les mutex peuvent être partagés ou non entre les différentes applications exécutées sur le poste. Il suffit d'indiquer le mode de partage des mutex lors de leur création (fonction [MutexCrée](1000019022.md)).

### Les fonctions de gestion des mutex
Les fonctions du WLangage spécifiques à la gestion des mutex sont les suivantes :

| [MutexCrée](1000019022.md) | Crée explicitement un mutex. |
| --- | --- |
| [MutexDébut](1000019023.md) | Bloque le thread courant en attendant que le mutex soit libre. |
| [MutexDétruit](1000019025.md) | Détruit explicitement un mutex. |
| [MutexFin](1000019024.md) | Signale que le thread libère le mutex. |
