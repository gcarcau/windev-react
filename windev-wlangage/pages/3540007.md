# Centre de Contrôle HFSQL : Optimiser et réparer les fichiers de données

> **Disponible :** **WINDEV** (Windows, Linux, Java, Etats et Requêtes, Code Utilisateur (MCU)) · **WEBDEV** (Windows, Linux, PHP) · **WINDEV Mobile** (Android, Widget Android, iPhone/iPad, Widget IOS, Apple Watch, Mac Catalyst)

## Présentation

Le Centre de Contrôle HFSQL permet d'optimiser et de réparer les fichiers de données HFSQL, aussi bien en mode Classic qu'en mode Client/Serveur.
Deux modes d'optimisation sont disponibles :

- Optimisation synchrone : L'optimisation est bloquante : la fenêtre de paramétrage de l'optimisation reste affichée pendant la réindexation.
- Nouveauté Abonnement
  Optimisation asynchrone : l'optimisation est lancée en tâche de fond sur le serveur. La fenêtre de paramétrage de l'optimisation peut être fermée. Le résultat de l'optimisation est affiché dans l'onglet "Optimisations" disponible pour les bases de données.
  Remarque : L'activation du mode asynchrone est effectué dans les [options du Centre de Contrôle HFSQL](3540001.md).
  **Attention** : Cette fonctionnalité est disponible uniquement dans la version Abonnement à partir de WINDEV Suite 2025 Update 2.
  Pour plus de détails, consultez [Utiliser les nouveautés de WINDEV Suite 2025 spécifiques à l'abonnement](1410087359.md).

### Lancer l'optimisation et la réparation des fichiers de données
Pour lancer l'optimisation et la réparation d'un (ou de plusieurs) fichier de données :

1. Connectez-vous si nécessaire à un serveur HFSQL et affichez la description d'une des bases de données ou d'un fichier de données (double-clic sur le nom de la base de données ou d'un fichier de données dans l'arborescence).
2. Dans le ruban, cliquez sur "Optimiser et réparer". La fenêtre d'optimisation s'affiche :
  - en mode synchrone :
  - Nouveauté Abonnement
    en mode asynchrone.
3. Spécifiez les options voulues.
4. Démarrez l'optimisation des fichiers de données.

Nouveauté Abonnement
**Remarque** : Si l'optimisation a été effectuée en mode asynchrone, l'onglet "Optimisations" dans les caractéristiques de la base de données. Cet onglet affiche le résultat des optimisations réalisées durant les dernières 48 heures. Il est possible si nécessaire de relancer une optimisation depuis cet onglet.

## Options d'optimisation et de réindexation

### Paramétrage des options d'optimisation
Les différentes options sont les suivantes :

- **Vérifier les index** : Vérifie la cohérence entre l'index et les fichiers de données.
- **Optimiser la vitesse des index (re-calcul des statistiques)** : Optimise les index en calculant les statistiques sur les index. Ces statistiques permettent d'optimiser les filtres, les requêtes et les vues HFSQL.
  Remarque : Plus le fichier de données est modifié et moins les statistiques reflètent le contenu du fichier de données HFSQL. Plus le fichier de données contient d'enregistrements et moins la modification d'un enregistrement a d'impact sur les statistiques.
- **Reconstruire les index (classique + full-text)** : Optimise l'accès aux enregistrements du fichier de données et re-calcule les statistiques. Tous les enregistrements rayés sont automatiquement supprimés. Si cette option est activée, les options de paramétrage avancé peuvent être sélectionnés.
- **Reconstruire les index et corriger les mémos endommagés** : Optimise la totalité du fichier de données, de son index et ses mémos. Si cette option est activée, les options de paramétrage avancé peuvent être sélectionnés.
- **Compacter les mémos** : Optimise la totalité du fichier de données, de son index et ses mémos. Les mémos seront compressés.
  Remarques :
  - Le fichier de données est recréé : la date de dernière écriture du dernier enregistrement (obtenue par la fonction [HDateEnreg](3044338.md)) est remise à la date du jour.
  - Les rubriques de type Horodatage sont également modifiées et correspondent à la date du jour, au moment où l'optimisation est effectuée.

Si l'option **"Optimiser sans bloquer les postes clients"** est cochée, la ré-indexation est effectuée en tâche de fond et les applications clientes ne seront pas arrêtées.
**Attention** : Cette option est prise en compte uniquement pour des fichiers de données HFSQL Client/Serveur.

**Remarques** :

- Mis à part l'option "Optimiser la vitesse des index (re-calcul des statistiques)", toutes les modes d'optimisation entraînent le blocage des fichiers de données pendant l'optimisation. Les utilisateurs sont informés que le fichier de données est en cours de maintenance.
- Lorsque la réindexation est effectuée, le contexte HFSQL en cours est rétabli (sauf si l'option de compression des mémos a été choisie).

### Paramètres avancés de réindexation
Les paramètres avancés sont les suivants :

- **Supprimer les enregistrements endommagés**
  Si cette option est cochée, les enregistrements endommagés sont automatiquement supprimés.
- **Supprimer les enregistrements inactifs (supprimés ou rayés)**
  Si cette option est sélectionnée, les enregistrements rayés sont définitivement supprimés.
  **Rappel** : Lorsqu'un enregistrement est rayé, il est supprimé logiquement et pourra éventuellement être récupéré par la suite. L'enregistrement est encore présent dans le fichier de données. La suppression des enregistrements rayés supprime définitivement ces enregistrements et permet ainsi d'optimiser la taille du fichier de données.
- **Densité de l'index**
  Correspond au taux de remplissage des index. Par défaut, ce taux a pour valeur 80.
  Plus ce taux est important, plus l'index est dense et de petite taille. Dans ce cas, les parcours, recherches, filtres et requêtes sont plus rapides. Les ajouts d'enregistrements et les modifications d'enregistrements pourront être ralentis.
  Plus ce taux est faible, moins l'index sera dense et plus sa taille sera importante. Dans ce cas, les parcours, recherches, filtres et requêtes seront ralentis. Les ajouts d'enregistrements et les modifications d'enregistrements seront plus rapides.
  Attention : ce paramètre est utilisable uniquement sur les fichiers de données au format HFSQL Classic ou Client/Serveur.
- **Alphabet**
  Par défaut, l'alphabet du fichier de données est conservé. Mais il est possible d'effectuer une ré-indexation en changeant l'alphabet du fichier de données. Dans ce cas, le nouvel alphabet sera pris en compte lors de la ré-indexation. Les tris (ou les recherches) sur des clés de type chaîne (chaînes, caractères, date et heure) seront effectuées selon cet alphabet.
