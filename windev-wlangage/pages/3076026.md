# telRépondAppel (Fonction)

> **Disponible :** **WINDEV** (Windows, Etats et Requêtes, Code Utilisateur (MCU))

Répond à un appel entrant détecté.
> _(WINDEV)_ Le modem décroche et l'appel va pouvoir être traité par le modem (utilisation d'un répondeur par exemple).

## Exemple

> _(WINDEV, Etats et Requêtes, Code Utilisateur (MCU))_ PROCÉDURE DetectionAppel(nIDService, nIDAppel, nStatut)
// Décroche la ligne pour répondre
telRépondAppel(nIDAppel)
// Enclenchement du répondeur
telJoue("repondeur.wav", telJoueBoucle, nIDAppel)
// Si la touche étoile a été appuyée
// le répondeur est stoppé
SI Position(telToucheEnfoncée(nIDAppel), "*") = Vrai ALORS
 telArrête(nIDAppel)
FIN

## Syntaxe

```wlangage
<Résultat> = telRépondAppel([<Identifiant de l'appel>])
```

`<Résultat>` *Booléen*
> - Vrai si la prise d'appel a réussi,
> - Faux dans le cas contraire.
`<Identifiant de l'appel>` *Entier optionnel*
> Identifiant de l'appel à manipuler. Cet identifiant est connu dans la procédure WLangage appelée par la fonction [telDémarreDétectionAppel](3076029.md). Si ce paramètre n'est pas spécifié, l'appel en cours est manipulé.

## Remarques

### Limitation
Il n'est pas possible d'appeler la fonction **telRépondAppel** dans la procédure de détection d'appels (définie grâce à la fonction [telDémarreDétectionAppel](3076029.md)).

### Configuration nécessaire
Les fonctions de téléphonie utilisent la technologie TAPI 2.0 et/ou la technologie TAPI 3.1. Ces technologies sont utilisables sur tous les systèmes.

**Composante : wd300com.dll**
