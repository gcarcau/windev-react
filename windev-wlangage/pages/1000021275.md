# SignalManuel (Type de variable)

> **Disponible :** **WINDEV** (Windows, Linux, Etats et Requêtes, Code Utilisateur (MCU)) · **WEBDEV** (Windows, Linux) · **WINDEV Mobile** (iPhone/iPad, Apple Watch)

Le type **SignalManuel** permet de gérer un signal manuel. Un signal manuel permet de faciliter la synchronisation entre plusieurs threads.
Un signal manuel est modifié uniquement par la fonction [SignalModifie](3077017.md).

**Remarque** : Il est préférable d'utiliser une variable de type [SignalAutomatique](1000021270.md) ou **SignalManuel** pour créer un signal plutôt que le nommer en utilisant une chaîne de caractères. En effet, dans le cas de l'utilisation d'une variable, il est possible de :

- gérer la portée de la variable,
- éviter que 2 signaux aient le même nom dans 2 threads différents.

## Exemple

```wlangage
// THREAD PRINCIPAL
//------------------
// Définition du signal
s est un SignalManuel
// Lancement du thread
ThreadExécute("Thread", threadNormal, ProcThread, s)
// Code en parallèle du thread
...
// On attend le signal déclenché par le thread
SignalAttend(s)
```

```wlangage
// THREAD SECONDAIRE
// ----------------------
PROCÉDURE ProcThread(s)

// Code dans le thread
...
// Débloque le thread principal
SignalOuvre(s)
```

## Déclaration

#### Déclarer un signal manuel (syntaxe simple)

```wlangage
MaVariable est un SignalManuel
```

Dans ce cas, le signal manuel créé est dans l'état fermé.

#### Déclarer un signal manuel (syntaxe avancée)

```wlangage
MaVariable est un SignalManuel(<Etat initial>)
```

`<Etat initial>` *Constante de type Entier*
> Etat du signal à sa création :
>
> | *signalOuvert* | Le signal est ouvert lors de sa création. |
> | --- | --- |
> | *signalFermé* | Le signal est fermé lors de sa création. |

## Remarques

### Utilisation des variables de type SignalManuel
Les variables de type **SignalManuel** peuvent être utilisées pour synchroniser des threads entre eux dans les fonctions :

- syntaxe classique :
  | [SignalAttend](3077007.md) | Bloque le thread en cours en attendant que le signal spécifié soit ouvert. |
  | --- | --- |
  | [SignalFerme](1000021272.md) | Ferme un signal de synchronisation entre plusieurs threads. |
  | [SignalOuvre](1000021271.md) | Ouvre un signal de synchronisation entre plusieurs threads. |
- syntaxe préfixée :
  | [<Variable SignalManuel>.Attend](1000024381.md) | Bloque le thread en cours en attendant que le signal spécifié soit ouvert. |
  | --- | --- |
  | [<Variable SignalManuel>.Ferme](1000024382.md) | Ferme un signal de synchronisation entre plusieurs threads. |
  | [<Variable SignalManuel>.Ouvre](1000024384.md) | Ouvre un signal de synchronisation entre plusieurs threads. |

Lors d'un appel à la fonction [SignalOuvre](1000021271.md) (ou [<Variable SignalManuel>.Ouvre](1000024384.md)), le signal reste ouvert :

- tous les threads en attente sont libérés,
- tous les threads qui atteindront le signal plus tard passeront sans attente.

Lors d'un appel à la fonction [SignalFerme](1000021272.md) (ou [<Variable SignalManuel>.Ferme](1000024382.md)), le signal est fermé : tous les threads qui atteindront le signal resteront bloqués.
