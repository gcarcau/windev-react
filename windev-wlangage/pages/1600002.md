# Administrateur SaaS - Ajouter un site

> **Disponible :** **WEBDEV** (Windows, Linux)

## Présentation

L'ajout d'un site SaaS permet de déclarer un site SaaS déployé sur un Serveur d'Application WEBDEV à un Webservice SaaS afin de permettre son utilisation.
Cette opération doit être réalisée après le déploiement du site.

**Remarque** : Cette opération est équivalente à l'utilisation de la fonction [SaaSAdminAjouteSite](1000019102.md).

## Comment le faire ?

Pour ajouter un site SaaS, depuis le menu principal de l'Administrateur SaaS, sélectionnez l'option "Sites .. Ajouter un site".
**Rappel** : L'Administrateur SaaS est situé sur le Serveur d'Application hébergeant le Webservice SaaS qui contrôle le site.

Les éléments suivants sont demandés :

| **Elément** | **Rôle** |  |
| --- | --- | --- |
| *Nom du site* | Il s'agit du nom de déploiement du site WEBDEV. Ce nom a été fourni lors de la procédure de déploiement du site dans l'assistant d'installation. Par défaut, il s'agit du nom du projet. **Remarque** : Ce paramètre est sensible à la casse. |  |
| *Mode de gestion des données* | Plusieurs choix sont possibles :  \| Mode de gestion des données \| Avantages \| Inconvénients \| \| --- \| --- \| --- \| \| Pas de base de données \| \| \| \| Une base de données unique partagée par tous les comptes clients \| - Possibilité de mutualiser des éléments entre les différents clients (si le site utilise des mémos volumineux, ils n'ont pas à être recopiés pour chaque client). - Simplification de la maintenance de la base de données : une seule sauvegarde à réaliser, une seule modification automatique en cas d'évolution de l'analyse du site. \| - Risque de fuite d'informations entre les différents comptes clients en cas de bug dans le site. - Impossibilité de livrer une sauvegarde de sa base à un client sans fournir la totalité des données. \| \| Une base de données par compte client \| - Grande sécurité contre la fuite d'informations : chaque compte client ne peut accéder qu'à sa base. Dans le cas de l'utilisation d'une base HFSQL en mode Client/Serveur, cette sécurité est encore accrue par la création d'un compte HFSQL pour chaque compte client SaaS. - Possibilité de sauvegarder séparément la base de données de chaque client et de livrer les sauvegardes. - La maintenance de la base d'un client n'a pas d'incidence sur les autres. - La programmation est simplifiée puisqu'il n'est pas nécessaire de différencier les enregistrements des différents clients dans la base. \| - Impossibilité d'accéder aux données d'un compte client depuis un autre site \| |  |
|  |  |  |
| Mode de gestion des données | Avantages | Inconvénients |
| Pas de base de données |  |  |
| Une base de données unique partagée par tous les comptes clients | - Possibilité de mutualiser des éléments entre les différents clients (si le site utilise des mémos volumineux, ils n'ont pas à être recopiés pour chaque client). - Simplification de la maintenance de la base de données : une seule sauvegarde à réaliser, une seule modification automatique en cas d'évolution de l'analyse du site. | - Risque de fuite d'informations entre les différents comptes clients en cas de bug dans le site. - Impossibilité de livrer une sauvegarde de sa base à un client sans fournir la totalité des données. |
| Une base de données par compte client | - Grande sécurité contre la fuite d'informations : chaque compte client ne peut accéder qu'à sa base. Dans le cas de l'utilisation d'une base HFSQL en mode Client/Serveur, cette sécurité est encore accrue par la création d'un compte HFSQL pour chaque compte client SaaS. - Possibilité de sauvegarder séparément la base de données de chaque client et de livrer les sauvegardes. - La maintenance de la base d'un client n'a pas d'incidence sur les autres. - La programmation est simplifiée puisqu'il n'est pas nécessaire de différencier les enregistrements des différents clients dans la base. | - Impossibilité d'accéder aux données d'un compte client depuis un autre site |
| *Paramètres d'accès aux données* | Selon le mode de gestion des données choisi, il convient d'indiquer :  - **dans le cas d'une base HFSQL Client/Serveur** : les paramètres de connexion au serveur HFSQL ainsi que le nom de la base de référence (optionnelle) qui sera dupliquée pour créer chaque base des comptes clients. - **dans le cas d'une base HFSQL Classic** : le nom du répertoire des fichiers de données de référence.  **Note** : les répertoires de données des différents comptes clients sont localisés sur le Serveur d'Application hébergeant le site, dans le répertoire des données du compte WEBDEV propriétaire du site. |  |
